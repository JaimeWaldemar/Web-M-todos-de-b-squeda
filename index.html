La primera mención de la búsqueda binaria es de 1946, pero pasó 16 años hasta existir una implementación correcta para cualquier tamaño de arreglo.

Fundamentos computacionales

¿Qué es “buscar” en Computación?

Buscar es localizar dentro de una colección de datos el elemento que cumple una condición — normalmente, aquel cuya clave es igual a un valor objetivo. Es una de las operaciones más ejecutadas de toda la informática: cada consulta a una base de datos, cada autocompletado y cada buscador web resuelven, en el fondo, un problema de búsqueda.

La diferencia entre un algoritmo de búsqueda correcto y uno eficiente se mide en comparaciones: cuántas veces preguntamos “¿es este?”. En una agenda de un millón de contactos, buscar de forma secuencial puede costar un millón de comparaciones; con búsqueda binaria, como máximo 20; y con tablas hash, normalmente 1. Esta página explora las tres filosofías que hacen posible esa diferencia.

📜 Breve historia de la búsqueda

  1. 1946
    John Mauchly menciona la búsqueda binaria en las conferencias de la Moore School (primer registro conocido del método).
  2. 1953
    Hans Peter Luhn (IBM) concibe la dispersión (hashing) para recuperar información de forma casi instantánea.
  3. 1962
    Se publica la primera implementación correcta de la búsqueda binaria para arreglos de cualquier tamaño (problema sutil de bordes).
  4. 1973
    Donald Knuth recopila y analiza estos métodos en The Art of Computer Programming, Vol. 3: Sorting and Searching, la referencia canónica.

Módulo 6.1 · Complejidad lineal O(n)

🔍 Búsqueda Secuencial (Lineal)

Recorre la colección elemento por elemento, desde la posición 0, comparando cada valor con el objetivo. Se detiene al encontrarlo o al terminar el arreglo. Es el único método que no exige ningún requisito sobre los datos: funciona igual en listas ordenadas o desordenadas.

📖 Metáfora: buscar una palabra en un libro leyendo hoja por hoja desde la primera — lento, pero imposible de fallar.

⚡ Rendimiento y reglas

  • Requisito: ninguno (acepta datos desordenados).
  • Mejor caso: O(1) — el objetivo está en la primera posición.
  • Caso promedio: O(n/2) → sigue siendo lineal.
  • Peor caso: O(n) — al final o no existe.
  • Espacio extra: O(1).
  • Variaciones: búsqueda con centinela, recorrido inverso o salir al encontrar.
✔ Ideal para colecciones pequeñas o que cambian constantemente.

💻 El algoritmo

Para cada índice i: si lista[i] == objetivo → devolver i. Si el bucle termina, devolver -1.

// Búsqueda secuencial en C#
static int BusquedaSecuencial(int[] lista, int objetivo) {
    for (int i = 0; i < lista.Length; i++) {
        if (lista[i] == objetivo)
            return i;          // posición encontrada
    }
    return −1;                 // no existe
}

int[] numeros = { 15, 8, 42, 4, 23 };
Console.WriteLine(BusquedaSecuencial(numeros, 42));  // → 2
ALGORITMO BusquedaSecuencial(lista, objetivo)
  PARA i ← 0 HASTA longitud(lista) − 1 HACER
      SI lista[i] = objetivo ENTONCES
          DEVOLVER i
      FIN SI
  FIN PARA
  DEVOLVER −1
FIN ALGORITMO

🛡️ Variante: búsqueda con centinela

Se planta el objetivo en la última posición del arreglo: entonces el bucle está garantizado que lo encontrará y ya no necesita comparar “¿llegué al final?” en cada vuelta. En arreglos enormes ahorra una comparación por iteración (Weiss, 2014). 

// Secuencial con centinela
static int BusquedaCentinela(int[] lista, int objetivo) {
    int ultimo = lista[lista.Length − 1];
    lista[lista.Length − 1] = objetivo;   // plantar el centinela
    int i = 0;
    while (lista[i] != objetivo)          // una sola comparación por vuelta
        i++;
    lista[lista.Length − 1] = ultimo;     // restaurar el dato
    return (i < lista.Length − 1 || ultimo == objetivo) ? i : −1;
}

🧮 ¿Por qué el promedio es (n+1)/2?

Si el objetivo es igual de probable en cualquier posición, el costo esperado es:

1·(1/n) + 2·(1/n) + … + n·(1/n) = (n+1)/2 ≈ n/2

Inspeccionas “la mitad del arreglo” en promedio, y esa mitad sigue creciendo con n: por eso el caso promedio se reporta como O(n) y el método no escala.

⚠️ Errores comunes y consejo de examen

  • Empezar el recorrido en el índice 1: el primero es el 0.
  • No interrumpir al hallar el valor (olvidar break): pierdes el mejor caso O(1).
  • Olvidar devolver -1 al terminar: la función regresa None/undefined y quien la llame puede fallar.
✔ Consejo: si el ejercicio pide todas las ocurrencias, no rompas el bucle — acumula cada índice coincidente en una lista y devuélvela al final.

Módulo 6.2 · Complejidad logarítmica O(log n)

⚡ Búsqueda Binaria

Divide repetidamente el intervalo de búsqueda a la mitad: compara el valor central con el objetivo; si es menor, descarta la mitad izquierda; si es mayor, descarta la derecha. Cada comparación elimina la mitad restante, por eso logra log₂(n) comparaciones como máximo.

📚 Metáfora: buscar una palabra en un diccionario — abres por la mitad y decides si seguir a la izquierda o a la derecha.

⚡ Rendimiento y reglas

  • Requisito indispensable: los datos DEBEN ESTAR ORDENADOS.
  • Mejor caso: O(1) — el objetivo cae en el centro.
  • Caso promedio / peor: O(log n).
  • Espacio extra: O(1) iterativa.
  • Escala: 1 000 000 elementos ⇒ ≤ 20 comparaciones.
  • Ojo: si hay que ordenar antes, se invierte O(n log n) una única vez.
✔ Ideal para colecciones grandes y estables ya ordenadas.

💻 El algoritmo

Variables inicio, fin y medio. Comparar lista[medio] con objetivo y reducirla ventana a la mitad.

// Búsqueda binaria en C# (iterativa)
static int BusquedaBinaria(int[] lista, int objetivo) {
    int inicio = 0, fin = lista.Length − 1;
    while (inicio <= fin) {
        int medio = inicio + (fin − inicio) / 2;  // evita el desbordamiento
        if (lista[medio] == objetivo)
            return medio;
        else if (lista[medio] < objetivo)
            inicio = medio + 1;    // descarta izquierda
        else
            fin = medio − 1;       // descarta derecha
    }
    return −1;
}

int[] datos = { 3, 9, 14, 18, 25, 31, 42, 55, 68 };
Console.WriteLine(BusquedaBinaria(datos, 25));   // → 4

      medio ← (inicio + fin) DIV 2
      SI lista[medio] = objetivo ENTONCES

🧮 La tabla mágica de log₂(n)

⌈log₂ n⌉ comparaciones3461020

Cada vez que el arreglo duplica su tamaño, la binaria paga una sola comparación extra. Esa es la esencia del crecimiento logarítmico: pasas de 1 000 a 1 000 000 de datos y el peor caso va de 10 a 20.

🧠 Versión recursiva (misma complejidad)

// Recursiva: O(log n) de tiempo, O(log n) de pila
static int BinariaRec(int[] lista, int objetivo, int lo, int hi) {
    if (lo > hi)                    // ventana vacía
        return −1;
    int m = lo + (hi − lo) / 2;
    if (lista[m] == objetivo)
        return m;
    if (lista[m] < objetivo)
        return BinariaRec(lista, objetivo, m + 1, hi);
    return BinariaRec(lista, objetivo, lo, m − 1);
}

⚠️ Errores comunes y consejo de examen

  • Calcular el centro con (lo + hi) / 2 directo en Java/C#: desborda enteros con arreglos de más de 2³⁰ elementos (la famosa falla de 9 años en Java). El código de arriba ya lo evita con inicio + (fin − inicio) / 2.
  • Aplicarla a datos desordenados: descarta la mitad equivocada y "hallará" o perderá valores al azar.
  • Actualizar fin = medio o inicio = medio en vez de medio ± 1: se crean ventanas que nunca terminan (bucle infinito).
✔ Consejo: trata el valor del medio como “visitado y descartado”; por eso los bordes se mueven con el ± 1 y el algoritmo siempre termina.

Módulo 6.3 · Complejidad constante O(1) promedio

🛡️ Búsqueda Hash (Dispersión)

No compara elementos: aplica una función de dispersión a la clave para calcular directamente el índice donde debe estar el dato — típicamente hash(clave) % tamaño. Si la función reparte bien las claves, el acceso es de tiempo constante, sin importar cuántos elementos haya.

🔑 Metáfora: los casilleros de un gimnasio — la llave contiene un número que te dice en qué puerta está tu mochila; no abres puertas una por una.

⚡ Rendimiento y reglas

  • Mapeo directo: índice = Hash(clave) % tamañoTabla.
  • Caso ideal / promedio: O(1).
  • Peor caso (todas colisionan): O(n).
  • Espacio extra: O(n) para la tabla.
  • Colisión: dos claves distintas caen en el mismo índice. Se resuelve con sondeo lineal, encadenamiento, etc.
  • Factor de carga: ocupados / total. Sobre ≈0.7 cae el rendimiento.
⚠ Requiere diseñar bien la función hash; no guarda orden.

💻 El algoritmo

Tabla con sondeo lineal para colisiones: si el casillero está ocupado, prueba el siguiente.

// Tabla hash con sondeo lineal
class TablaHash {
    int?[] tabla;
    public TablaHash(int tamano = 7) {
        tabla = new int?[tamano];        // casillas vacías = null
    }

    int FuncionHash(int clave) {
        return clave % tabla.Length;
    }

    public void Insertar(int clave) {
        int h = FuncionHash(clave);
        while (tabla[h] != null)        // ¿colisión?
            h = (h + 1) % tabla.Length; // sondeo lineal
        tabla[h] = clave;
    }

    public int Buscar(int clave) {
        int h = FuncionHash(clave);
        while (tabla[h] != null) {
            if (tabla[h] == clave)
                return h;
            h = (h + 1) % tabla.Length;
        }
        return −1;                      // no existe
    }
}
ALGORITMO InsertarEnTablaHash(tabla, clave)
  h ← funcion_hash(clave)             // clave mod N
  MIENTRAS tabla[h] ≠ VACÍO HACER     // colisión
      h ← (h + 1) mod N               // sondeo lineal
  FIN MIENTRAS
  tabla[h] ← clave
FIN ALGORITMO

🧪 Tres recetas de función hash (enteros)

  • Módulo — hash(k) = k % N. La que usan los simuladores: rápida, pero con N par agrupa claves pares e impares por separado.
  • Plegado (folding) — divide la clave en bloques, los suma y aplica módulo: útil para códigos largos (cédulas, Códigos de barras).
  • Multiplicación — ⌊(k·A % 1)·N⌋ con A ≈ 0.6180 (razón dorada): reparte mejor en tablas de tamaño potencia de 2.

Regla de oro (Knuth, 1998): si usas módulo, elige un N primo para que el reparto sea uniforme.

🔤 ¿Y con cadenas de texto?

Las claves no son siempre números. La técnica estándar es el hash polinomial: cada letra aporta su valor multiplicado por una base: 

// Hash polinomial para texto
static int HashTexto(string clave, int tamano) {
  int h = 0;
  foreach (char c in clave)
    h = (h * 31 + c) % tamano;
  return h;
}
// HashTexto("ANA", 10) devuelve siempre el mismo índice

En C#, Dictionary<string, T>, HashSet<T> y los switch sobre string usan este principio (con hashes semilla aleatoria por sesión para defenderte de colisiones malintencionadas).

⚠️ Errores comunes y consejo de examen

  • Dar por bueno un tamaño par o potencia de 10: claves consecutivas mandarán todo a muy pocas casillas. Usa N primo.
  • Ignorar el caso tabla llena: con sondeo lineal el bucle while se ciclaría; siempre valida el límite de sondeos.
  • No planificar redimensionar (rehash) cuando el factor de carga pasa ≈ 0.7: las colisiones se disparan y el O(1) se convierte en O(n).
✔ Consejo de examen: una buena función hash debe ser determinista (misma clave → mismo índice), uniforme y rápida. Si no cumple las tres, es sospechosa.

Los tres métodos · Al alcance de tu mano

💡 ¿Dónde los usas cada día?

No son teoría abstracta: los tres métodos viven dentro del software que usas a diario — y cada uno gana en su propio terreno.

🔍

Secuencial en tu día

  • La agenda muestra contactos recientes en una lista corta: la agenda simplemente la recorre.
  • El campo de búsqueda de tablas pequeñas (carrito, mis descargas) revisa ítem por ítem.
  • Contar cuántas veces aparece un valor: exige ver todas las ocurrencias.
⚡

Binaria en tu día

  • Autocompletado del teclado: la lista de sugerencias está ordenada y se recorta a mitades.
  • "Buscar en documento" de lectores PDF y wikis.
  • El seek de un video: busca el fotograma por índice de tiempo.
  • Bisección: hallar raíces de ecuaciones en métodos numéricos.
  • En el sistema operativo (Tanenbaum, 2009): Linux organiza sus regiones de memoria en un árbol binario rojo-negro para localizar direcciones rápido, y NTFS indexa los nombres de archivos de directorios grandes con árboles B+, estructuras pensadas para búsqueda.
🛡️

Hash en tu día

  • Dictionary/HashSet de C#, dict/set de Python y los objetos de JavaScript.
  • Índices hash de bases de datos (SQLite, MySQL) y cachés como Redis.
  • Checksums de descargas (SHA-256) y firmas digitales.
  • Claves de productos (SKU) en almacenes en tiempo constante.
  • Dentro del sistema operativo (Tanenbaum, 2009): los directorios con miles de archivos usan una tabla de hash (con claves que colisionan unidas en listas enlazadas) en vez de la búsqueda lineal, y la memoria virtual de máquinas de 64 bits localiza páginas en tablas invertidas dispersadas por hash.
✔ Los tres coexisten: el secreto de un buen ingeniero no es "elegir el mejor", sino reconocer cuándo cada uno es el mejor.

🏆 Retos con solución plegable

Intenta resolver cada reto en tu cuaderno, a mano; después despliega la solución y compara. Son exactamente lo que suele preguntarse en examen para la Unidad 6.

🧩 Reto 1 · Traza de la binaria

Arreglo ordenado [4, 8, 15, 16, 23, 42]. ¿Cuántas comparaciones cuesta hallar el 23? Haz la traza completa.

Ver solución

Comparación 1: mid = (0+5)/2 = 2 → 15 < 23 ⇒ descarta [0…2], lo = 3.
Comparación 2: mid = (3+5)/2 = 4 → 23 = 23 ⇒ encontrado en [4] con 2 comparaciones. Aprobaste en dos pasos donde la secuencial gastaría 5.

🧩 Reto 2 · Mejor caso secuencial

¿Por qué la búsqueda secuencial, siendo O(n), puede terminar en una comparación? ¿En qué condición?

Ver solución

Cuando el objetivo está en la primera posición [0]: la primera comparación coincide y el algoritmo devuelve 0 y rompe. Mejor caso O(1). Lo mismo pasa en la carrera de esta página cuando el objetivo cae al inicio del arreglo.

🧩 Reto 3 · Colisión en búsqueda hash

Tabla de N = 10 con sondeo lineal. Insertas 3, 13, 23. ¿Cuántas comparaciones cuesta BUSCAR el 23?

Ver solución

3 → [3] ✔ · 13 → [3] ocupado ⇒ [4] · 23 → [3] ≠, [4] ≠, [5] = 23 ✔
La clave 23 termina en [5]: una búsqueda necesita 3 comparaciones (casillas 3, 4 y 5). La colisión "encadenó" las tres claves hacia índices mayores.

🧩 Reto 4 · Binaria recursiva en C#

Escribe la versión recursiva de la búsqueda binaria que devuelva el índice o −1.

Ver solución 
// Envoltura: arranca con la ventana completa
static int BinariaRec(int[] lista, int x) {
  return BinariaRec(lista, x, 0, lista.Length − 1);
}
static int BinariaRec(int[] lista, int x, int lo, int hi) {
  if (lo > hi) return −1;           // ventana vacía
  int m = lo + (hi − lo) / 2;
  if (lista[m] == x) return m;
  return lista[m] < x
    ? BinariaRec(lista, x, m + 1, hi)
    : BinariaRec(lista, x, lo, m − 1);
}

🧩 Reto 5 · ¿Por qué exige orden?

¿Qué pasa exactamente si ejecutas la búsqueda binaria sobre datos desordenados? ¿Y por qué secuencial sí funciona?

Ver solución

La decisión de descartar media ventana solo es válida si “todo lo de la izquierda es menor y lo de la derecha mayor". Sin orden, el descarte puede eliminar el propio objetivo: devolverá −1 aunque exista. La secuencial no hace supuestos, por eso nunca falla (solo es lenta).

🧩 Reto 6 · Sondeo cuadrático y N primo

El sondeo cuadrático prueba h+1², h+2², h+3²…. ¿Por qué exige N primo y factor de carga menor a 0.5?

Ver solución

Con (h + i²) mod N, los saltos solo cubren la mitad de las casillas (pares de i² módulo N se repiten). Si N es primo, la mitad ≈ ⌊N/2⌋ casillas distintas se alcanzan y todas si α < 0.5: siempre queda una libre dentro del rango sondeable.

🧩 Reto 7 · Duplicados en secuencial

¿Qué devuelve busqueda_secuencial([−3, 7, 7, 7, 9], 7) y por qué solo devuelve un valor?

Ver solución

Devuelve 1: la primera ocurrencia. Como la función rompe el bucle al hallar, no revisa los duplicados de los índices 2 y 3. Para todas las ocurrencias habría que seguir recorriendo (caso de “múltiples ocurrencias" que viste en Variantes).
